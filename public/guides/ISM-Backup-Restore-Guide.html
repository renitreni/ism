1. Overview

The ISM Backup & Restore System is a powerful tool that allows you to create, download, and restore backups of your database. This ensures that your critical business data is always protected and can be recovered in case of accidental deletion, data corruption, or system failure.

Key Features:
  • ✅ Create backups of entire database or specific categories
  • ✅ Download backups for offsite storage
  • ✅ Restore data from any previous backup
  • ✅ Track backup history with detailed logs
  • ✅ Automatic daily, weekly, and monthly backups
  • ✅ JSON format (portable and universally compatible)

2. Accessing the Backup System

Prerequisites

  • You must be logged in to the ISM application
  • You must have administrator or super admin access
  • Sufficient disk space for backup files

Steps to Access

1 Login: Log in to your ISM application with your credentials
2 Navigate: Look for the "Backup & Restore" link in the main navigation menu (usually under Settings or Admin section)
3 Open: Click the link to open the Backup & Restore page

You should see a page with tabs: Backup, Restore, Backup Files, and History

3. How to Create Backups

Understanding Backup Categories

The system organizes your data into logical categories:

Category What It Includes Best Use
Purchase Orders (P.O) All purchase orders, details, and summaries Backup vendor purchases
Sales Orders (S.O) All sales orders, details, summaries, order forms Backup customer sales
Products & Categories Products, categories, supplies, galleries, tags Backup product catalog
Vendors All vendor information Backup supplier data
Customers All customer information Backup customer data
Expenses All expense records Backup cost tracking
Job Orders Job orders, statuses, and products Backup job data
Product Returns Returns, statuses, and details Backup return data
System Settings Users, preferences, settings, logs Backup system configuration

Backup Method 1: Create a Category Backup

Best for: Regular, organized backups of specific business areas

1 Open Backup Tab: Navigate to the Backup tab
2 Select Categories: Check the boxes next to the categories you want to backup
3 Use Helper Buttons:
  • Click "Select All" to select all categories at once
  • Click "Clear" to deselect all categories
4 Start Backup: Click the Backup Selected button
5 Wait for Completion: You'll see a processing message. Wait until the success message appears
6 Confirmation: You'll see a success message showing the backup filename (e.g., backup_sales_orders_2024-04-08_143022.json)

Backup Method 2: Create a Full Database Backup

Best for: Complete system backup, disaster recovery, archival

1 Open Backup Tab: Go to the Backup tab
2 Click Full Backup Button: Click the Backup All (Full) button
3 Confirm: A confirmation dialog will appear asking "This will create a complete backup of all data. Continue?"
4 Proceed: Click Yes, backup all! to proceed
5 Wait: Full backups may take from a few seconds to several minutes depending on your database size. You'll see a loading message
6 Success: You'll see a success message when complete
💡 Tip: Regular full backups are recommended for disaster recovery. Create one monthly and download it for offsite storage.

4. How to Download Backups

Why Download Backups?

  • Offsite Storage: Keep copies away from your server
  • Long-term Archive: Store past versions for compliance
  • Disaster Recovery: Have backups available if server is compromised
  • Migration: Transfer data to other systems or servers

Steps to Download a Backup

1 Open Backup Files Tab: Click on the Backup Files tab
2 View Backup List: You'll see a table with all available backups showing:
  • Filename (what was backed up and when)
  • File size (in KB, MB, or GB)
  • Date created
3 Select Backup: Find the backup file you want to download
4 Click Download: Click the blue ⬇️ Download button next to the file
5 Save File: Your browser will prompt you to save the file. Choose a location and click Save
6 Store Safely: Move the file to cloud storage (Google Drive, Dropbox) or external drive for long-term storage
✅ Best Practices for Downloaded Backups:
  • Label backups with dates (e.g., "backup_full_2024-04_april.json")
  • Keep copies in multiple locations (local + cloud + external drive)
  • Test restoration from backups periodically
  • Keep at least 3 recent backups available

5. How to Restore from Backups

⚠️ WARNING: Restoring from a backup will OVERWRITE your current data with the data from the backup. Make sure you have a current backup before restoring!

When to Restore

  • After accidental data deletion
  • After data corruption or inconsistency
  • To revert to a previous state
  • During disaster recovery

Restore Method 1: From Downloaded Backup File

Use this to: Restore a backup file you've saved on your computer

1 Open Restore Tab: Click on the Restore tab
2 Upload File: Click "Choose backup file..." button in the "Restore from Upload" section
3 Select File: Browse to your backup file (*.json) and click Open
4 Select Restore Type: Choose what to restore:
  • Full Restore (All Data) - Restores everything from the backup
  • Or select a category - Restores only that category (e.g., "Sales Orders")
5 Review Warning: Read the warning message carefully - you're about to overwrite data
6 Confirm: Click Restore Data button
7 Final Confirmation: A dialog will ask for final confirmation. Click "Yes, restore!"
8 Wait for Completion: You'll see a "Restoring data..." message. Wait until completion
9 Success: You'll see "Restored!" message showing what was recovered

Restore Method 2: From Server Backup

Use this to: Restore from a backup file already on your server

1 Open Restore Tab: Click on the Restore tab
2 Select Backup: In "Restore from Server Backup" section, click the dropdown "-- Select backup file --"
3 Choose File: Select a backup from the dropdown list (shows filename, size, and date)
4 Select Restore Type: Choose full restore or specific category
5 Confirm: Click Restore Data button
6 Final Confirmation: Confirm in the dialog that appears
7 Wait & Verify: Wait for completion and verify the restored data looks correct
💡 Tip: Always create a backup before performing major changes. If something goes wrong, you can restore the previous version.

6. Managing Backup Files

View Backup Files

  1. Go to Backup Files tab
  2. You'll see a table with all available backups
  3. Each backup shows: filename, size, and creation date
  4. Files are sorted with newest at the top

Delete Backup Files

  1. Go to Backup Files tab
  2. Find the backup you want to delete
  3. Click the red 🗑️ Delete button
  4. A confirmation dialog will appear
  5. Click "Yes, delete it!" to confirm
⚠️ Important: Deleted backups cannot be recovered. Only delete old or unnecessary backups. Always keep at least one recent backup!

View Backup History

  1. Go to History tab
  2. You'll see a log of all backup and restore operations
  3. Each entry shows:
    • Type (Backup or Restore)
    • Category backed up
    • Status (Success or Failed)
    • User who performed it
    • Date and time
✅ Use History to:
  • See which backups were successful
  • Identify when data was backed up
  • Track who made changes
  • Troubleshoot backup issues

7. Frequently Asked Questions

Q: How often should I backup my data?

A: It depends on your needs:

  • Critical systems: Daily or multiple times per day
  • Standard systems: Weekly
  • Archival: Monthly

The system includes automatic backups:

  • Daily at 2:00 AM
  • Weekly on Sundays at 3:00 AM
  • Monthly on the 1st at 4:00 AM

Q: How large are backup files?

A: File size depends on how much data you have:

  • Small backups (single category): 500 KB - 5 MB
  • Medium backups (multiple categories): 5 - 50 MB
  • Large backups (full database): 50 - 500 MB+

Q: How long does a backup take?

A: Timing depends on database size:

  • Single category: Less than 1 second
  • Multiple categories: 1-30 seconds
  • Full database: 1-5 minutes (or longer for very large databases)

During backup, don't close the browser tab or navigate away.

Q: Can I backup while others are using the system?

A: Yes! Backups use read-only queries, so other users can continue working normally. There's no performance impact.

Q: What if I restore by mistake?

A: This is why you need multiple backups:

  1. Immediately create a new backup of the current (incorrect) state
  2. Get the previous correct backup file
  3. Restore from the correct backup

Q: Can I restore just one category instead of everything?

A: Yes! When restoring, you can choose:

  • "Full Restore (All Data)" to restore everything
  • Or select a specific category to restore just that category

Q: Where are backup files stored on the server?

A: Backups are stored in: storage/app/backups/

This location is automatically managed by the system.

Q: Can I edit a backup file?

A: Backup files are JSON format (text-based) and technically can be opened in a text editor. However:

  • Not recommended - manual edits could corrupt the backup
  • If you need to modify data, it's better to restore to a test system first
  • For specific needs, contact your system administrator

Q: What if a backup fails?

A: If you see an error message:

  1. Check the error message - it often tells you what went wrong
  2. Verify you have disk space available
  3. Check that the database connection is working
  4. Try again after a few minutes
  5. Contact your administrator if the problem persists

  • Create regular backups - Don't wait for problems to occur

  • Always backup before major changes - System updates, data migrations, etc.
  • Keep multiple versions - Don't just keep the latest backup
